# 中文岗位检查器

`tools/cn_jd_check.py` 只检查本地文件或标准输入里的 JD，输出 JSON。示例命令：

```bash
python3 tools/cn_jd_check.py --in jd.txt
python3 tools/cn_jd_check.py --config config/cn_filters.json < jd.txt
```

默认读取 `config/cn_filters.json`；没有该文件时读取 `config/cn_filters.example.json`，并在 `warning` 中提示使用示例阈值。学历、学校、年龄、城市、户口和薪资的硬筛选结果在 `hard_filters`；示例阈值的失败会降为 `flag`。诈骗命中仍可导致 `reject`。脚本只使用 Python 标准库。

## 劳动权益提示

风险提示，非法律意见，以合同和当地人社部门解释为准。

`labor` 是命中明细列表，`hard_filters` 中的 `labor` 行是汇总。每条明细包含 `name`、`status`（仅 `flag` 或 `info`）、`evidence`、`detail`、`codes`、`legal_basis`、`source_urls` 和 `risk`。试用期时长和工资比例命中另带数值 `value`，单位分别是月和百分比。`legal_basis` 保存完整法条依据，`source_urls` 将其中每个条文名称映射到官方文本 URL，`detail` 附上上述固定风险提示。

| 项目 | 提示规则 |
| --- | --- |
| `probation_months` | 超过六个月为 `flag`；超过三个月且不超过六个月为 `info`，提示核对合同期限。识别数字、中文数字、半年、一年、半月等写法。三个月及以下不触发提示；这不代表已按合同期限核验。 |
| `probation_pay_ratio` | 试用期工资低于 80% 为 `flag`，识别百分比和折扣表述；八折、80% 不扣分。仍需核对工资比较基准和当地最低工资标准。 |
| `social_insurance` | 最低基数或标准、转正后起缴、试用期不缴、自愿放弃社保、不交公积金为 `flag`。六险二金、全额缴纳、按实际工资缴纳、补充公积金记为正向 `info`，`risk` 为 `false`。 |
| `outsourcing` | 外包、驻场、劳务派遣、人力外包、派遣制为 `info`，提示核对签约主体及用工形式。派遣相关依据只供核对派遣安排。 |
| `contract` | 不签合同、以实习协议代替劳动合同为 `flag`；在校生场景改为 `info`，提示结合实际用工性质核对。 |

否定表达会被排除，例如“不按最低基数缴纳”“禁止试用期不缴社保”“非劳务派遣”“严禁不签劳动合同”。正向福利也尊重否定，例如“无补充公积金”不会记为正向。

`labor.candidate_is_student` 可在自己的过滤配置中设为 `true` 或 `false`，优先于 JD 的表述；缺省或 `null` 时，用明确的在校生、在读本科等表述识别学生场景。单独出现“实习协议”不推断在校身份；没有在校身份信息时，保留合同风险提示以便核对。旧配置无需添加该字段也能使用。

每个命中 `flag` 的劳动权益维度扣 6 分，同一维度多次命中只扣一次，合计为 `labor_penalty`。`info` 不扣分。总分为 `max(0, 100 - jargon_penalty - scam_penalty - labor_penalty)`。劳动权益风险提示使总体结论至少为 `caution`，正向福利信息本身不触发 `caution`。劳动权益检查始终不会产生 `fail` 或独立导致 `reject`，即使使用自定义过滤配置也是如此。

例如“试用期6个月，打八折，五险一金按最低基数缴纳”：试用期为 `info`，最低基数为 `flag`，八折不扣分。仅有这段文本时，结论为 `caution`、`labor_penalty` 为 6、总分为 94。未命中时，汇总行为 `unknown`，不代表合同或福利安排已获核验。

## 年包与浮动薪资

`年薪20万`、`年包20-28万`等年包金额仍按除以12折算月薪参考值；未写薪数时，薪资行增加 `annual_months_unstated` 和“年包，未写薪数，建议问清几薪、年终奖是否保底”。明确写有 `13薪`、`14-16薪` 等薪数时不提示缺失；薪数区间按下限比较。

薪酬语境中的底薪、无责底薪、保底、提成、佣金，或明确组成月薪的绩效，会使 `parsed.salary.variable_pay` 为 `true`，薪资行增加 `base_plus_commission` 和“底薪+提成：到手不确定，问清底薪、提成规则和发放周期”。普通福利中的“绩效奖金”及职责中的业绩、绩效等词不单独触发。存在明确底薪/保底金额时，薪资底线比较使用该金额，不把综合收入、提成或绩效上限当作底薪。

这两类提示均为 `flag`，使结论至少为 `caution`，本身不扣分、不产生硬失败；已有薪资底线不匹配仍按原规则处理。未配置薪资阈值时也显示提示。

## 校招 / 实习与日薪

`campus.mode` 可选 `auto`（缺省）、`campus`、`intern`、`experienced`。auto 根据 JD 的校招/校园招聘/应届/实习/届别或在校要求选择模式，结果在 `parsed.campus.mode`；显式设置优先。模式描述招聘阶段，不证明候选人在读。旧配置无需修改。

`campus.graduation_year` 为候选人确认的四位毕业年份（如 2027，**虚构**示例），与 JD 的 `2027届`、`27届`、`2026-2027届` 等要求比较。`labor.candidate_is_student` 仍是唯一的候选人在读配置，true/false 优先，null 未知。`hard_filters` 的 `student_status` 和 `graduation_year` 行分别检查在校生要求和届别；未知信息为 `unknown`，不能从 JD 反推候选人。自定义阈值明确不匹配为 `fail`；「在校生优先」「2027届优先」等偏好项不匹配只为 `flag`，示例配置的失败也降为 `flag`。只写「应届」没有年份时需另行核对资格，工具不按当前年份猜测。

`日薪200-300元`、`200-300元/天`、`1000元/日`（数字均为虚构）输出 `parsed.salary.period: day`、`min_daily` / `max_daily`，单位为元/天；只与 `salary.min_daily` 比较上界能否达到底线，不比较 `min_monthly_k` 或 `min_months`，也不按天数估算月薪。没设日薪阈值时为 `unknown`。实习全职月薪仍按原月薪规则。时薪输出 `period: hour` 和 hourly 数值，混合日薪/时薪为 `mixed`，两者均保留证据待确认，不误用月薪。JD 同时给短周期报酬和其他金额时，优先输出短周期报酬，需人工确认适用阶段。

实习/校招模式本身**不豁免**劳动风险。在校生使用实习协议替代劳动合同的命中为 `info`，不扣分；明确非学生时仍为 `flag`，包括校招毕业生。学生身份未知时，现有劳动提示可依据 JD 的明确在校要求展示学生场景，但资格行依然为 `unknown`。协议名称或实习岗位名称本身不能证明学生身份，也不能确定劳动关系。所有 labor 项始终只是风险提示，不会产生 `fail` 或单独导致 `reject`。
