# 第五轮产品决策

日期：2026-10-21。口径：保守、可选启用、兼容旧配置。以下金额、日期及 JD 均为**虚构**示例，不代表任何候选人。工具只读手贴 JD，不联网、不抓取、不自动打招呼或投递。

## 五项决定与理由

| 决定 | 选择 | 理由 |
| --- | --- | --- |
| 雇主类型 | 默认不识别；可选展示 JD 明确自称及原文证据，仅 `info`、未经核验，始终不评分或硬筛选。 | 自称不能证明实际所有制、签约主体或编制，避免将猜测变成资格判断。 |
| 实习安排 | 三项配置各自默认关闭；确认的数据才比较，不匹配只 `flag`，不扣分、不拒绝。 | 每周出勤、持续月数、到岗时间常可协商，不应替用户设统一门槛。 |
| 年包与月薪 | 默认保留年包/12参与月薪比较；提供关闭该比较的开关及独立、默认关闭的年包软门槛；不新增保证月薪/保证奖金推算。 | 保留已有结果，同时允许区分现金月薪与年包；薪数和总包不能证明保底奖金。 |
| 弹性工作与965 | 默认保留弹性工作/弹性工作制扣6分；可选仅在同句明确非否定加班语境扣这6分。965只显示信息，不加分。 | 不静默改旧评分，也不让一句工时宣传抵消其他风险。 |
| 字体与纸张 | 保留中文CV拉丁衬线正文、求职信Raleway无衬线正文/列表；新中文求职信显式A4。 | 保留已验证的字体和换行；A4仅应用中文信件，避免影响共享类和其他语言。 |

## 配置与默认值

以下键写入用户自己的 `config/cn_filters.json`，不存在时仍按默认行为运行。`/setup` 只记录确认的值及启用意愿，不能从示例数字、JD或学校反推候选人信息。

| 配置键 | 默认 | 启用后的含义 |
| --- | --- | --- |
| `employer.detect_self_description` | `false` | `true` 才提取雇主自称，返回 `parsed.employer.mentions`。 |
| `availability.days_per_week` | `null` | 候选人可到岗天数，整数1–7；与JD每周天数下限比较。 |
| `availability.duration_months` | `null` | 候选人可持续月数，正有限数；与JD明确的实习持续月数下限比较。 |
| `availability.start_date` | `null` | 候选人最早到岗日，严格 `YYYY-MM-DD`；晚于JD明确带年份的最晚到岗日才提示。 |
| `salary.compare_annual_as_monthly` | `true` | 兼容旧版；显式设 `false` 才停止将解析为年包的月均值与 `min_monthly_k` 比较。 |
| `salary.min_annual_total_k` | `null` | 正有限数，**千元/年**；只比明确年包/年薪/年度总包/年度总薪酬或 `/年`、`/year` 金额的上界；上界低于门槛只提示。 |
| `jargon.flexible_work_overtime_only` | `false` | `true` 时，只有同一句（句号、分号、换行等分隔，逗号可连接）存在未否定的加班、随时待命、随叫随到、996/007/995，弹性工作才扣6分。其他扣分原样保留。 |

布尔键必须是 JSON 布尔值；数字不能是布尔、字符串、NaN、Infinity、零或负数。三个 availability 值均缺省或 null 时不新增比较行；只在 `parsed.campus.mode=intern` 时启用这些比较。显式指定 `campus.mode=intern` 仍只是招聘阶段，不证明在校身份。缺候选人信息不比较；有配置但缺可识别JD要求则 `unknown`。范围按下限；同类多处要求暂取最大下限、最早到岗日期，原文保留以便核对偏好项和可协商项。仅写「立即到岗」「2月1日」不补年份。上限式「每周4天以下」「实习3个月以内」不作为最低要求。

雇主识别限定「企业性质：国企」「单位性质：事业单位」「本公司是一家外企」等明确自称，支持国企、央企、事业单位、外企、民企及对应完整名称。客户、项目、学校、公司名称、央企子公司或“国企背景”不推断类型；否定不记为正向。多种明确自称均保留，不强行归类。每项有 `evidence`、`status: info`、`verified: false`，没有类型偏好分或拒绝配置。

年包软门槛与旧薪资行独立：不从月薪乘12/薪数计算年包，不把单独年终奖当总包，也不把底薪当年包。无明确总额、面议、只有开放下界（如「年包30万以上」）为 `unknown`；不会据此判低于门槛。若JD列多个明确年包档位，暂按最高上界能否达到门槛比较，不能保证候选人能拿到。总包可能含浮动部分，通过只表示上界达到目标，不表示保证收入。比如 `min_annual_total_k: 300` 对「年包20–28万」只提示；`min_monthly_k: 20` 对同一段文字仍按旧版规则处理，除非用户同时关闭年包月均比较。关闭开关不关闭真实月薪、日薪和 `min_months` 检查。保证月薪与保证奖金仍需人工核实，暂不新增机器门槛。

965 的信息保存在 `parsed.working_hours`；尊重否定并排除长数字、电话号码中的片段，不因此改变分数或结论。开启弹性工作开关可能按用户选择提高分数或将 caution 改成 pass；默认配置绝不发生该变化。

中文信件由规范导言区加载 `templates/cn/cncover.sty`，仅设置 A4，保留 `cover.cls` 的2.3cm页边距、字号与字体。无需 JSON 键；选择中文信件模板时才使用。历史生成文件不自动重写，自定义求职信仍遵循已验证的自定义版式。PDF需重检1页、A4尺寸及中文文本层。Linux上可验证编译和嵌字；Windows/macOS真机验收继续待办。

## 户籍简称与兼容性边界

识别京籍、沪籍、津籍、渝籍、粤籍及常见省级简称；粤籍指广东，绝不缩成广州。`hukou.has` 也接受「粤」「粤籍」等同义写法。正向简称遵循已有户籍筛选配置：必需项可失败，优先项只提示，示例配置失败降为提示。所需条件比优先条件优先；逗号分开的优先条件不串入下一项，证据选择实际要求原文。明确「京籍或沪籍」「京籍/沪籍」为 `mode: alternatives`，满足其一即可；再叠加独立条件时保守转人工核对。「不限京籍」「非京籍也可」「京籍非京籍均可」不产生正向要求。「仅限非京籍」「京籍勿投」等排除性或冲突说法返回 `mode: review`、`excluded_places` 和 `hukou_exclusion_review`，只提示核对，不根据空户籍列表推断符合，也不自动拒绝。学校城市不作为工作城市或候选人户籍证据。

旧配置的扣分公式、年包处理、薪数筛选、劳动权益提示及rank传递均保留；新增雇主/工时信息不参与算分。唯一默认资格识别扩展是本轮明确要求的户籍简称：以前漏掉的「限京籍」现在按已有配置检查，可能改变该类JD结论。无此简称的旧测试不改预期。新增软门槛即使使用自定义配置也不变硬失败，既有硬失败与诈骗否决仍保留。
