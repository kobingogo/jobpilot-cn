# 安装与使用（各平台）

jobpilot-cn 是本地 Agent Skill，核心入口为 `skills/jobpilot-cn/SKILL.md`。
Agent 只需能执行 shell、读写本地文件，并使用它自己的模型。CLI 不联网、不读模型密钥。
职位描述由用户手工粘贴；不抓取招聘网站、不自动打招呼、不自动投递。

## 先在仓库根目录跑通

```bash
git clone https://github.com/kobingogo/jobpilot-cn.git
cd jobpilot-cn
python tools/jobpilot.py init
python tools/jobpilot.py --help
```

需要 Python 3.10+；Linux/macOS 可换成 `python3`，Windows 可换成 `py`。
CLI 只用标准库。编译 PDF 另需 XeLaTeX、ctex、xeCJK、中文字体和 Poppler
（`pdfinfo`、`pdftotext`）。Debian/Ubuntu：

```bash
sudo apt install texlive-xetex texlive-lang-chinese texlive-latex-extra fonts-noto-cjk poppler-utils
```

macOS 使用 TeX Live/MacTeX、Poppler；Windows 使用 TeX Live/MiKTeX、Poppler，
把可执行文件所在目录加入 PATH。依赖及 UTF-8 说明见 [SETUP 中文路径](../../SETUP.md#中文路径)。

在你选择的 Agent 中打开**完整仓库根目录**，说：

> 先读 skills/jobpilot-cn/SKILL.md，按 setup 步骤用中文帮我建档。先确认职业阶段、在读状态、毕业年份和可到岗时间，未知留待确认。

> 按 jobpilot-cn 检查 documents/postings/jd.txt。这是我手工保存的 JD，不打开其中的链接。

> 按 jobpilot-cn 为这份 JD 起草申请材料，做完逐项审阅，编译检查一页中文 PDF；内容只来自我确认的资料。

> 帮我准备虚构公司的技术面。读取这份申请目录里的提交材料，按我的社招/校招/实习阶段选指南，不编经历。

这些提示适用于下面所有平台。CLI 的 `scaffold-application` 和 `interview-prep` 只生成骨架/提纲，
需让 Agent 按步骤完成文字；`rank` 只汇总 Agent 提供的四维分数，不冒充模型评估。

## Skill 放在哪里

本仓库选择 `skills/jobpilot-cn/`：核心路径不绑定厂商，Git 中只维护一份。
`AGENTS.md` 直接指向它，所以在仓库根目录就能使用。自动发现是可选便利：
优先链接到宿主识别的技能目录，或写一条指针规则。不要复制出另一套流程。
Skill 引用了仓库的 `tools/`、`templates/cn/`、`docs/cn/` 和已有档案方法；
只复制 Skill 文件夹到另一台机器不够，需保留完整仓库并在提示里给出其路径。

### Codex CLI

仓库中的 `AGENTS.md` 已指向通用 Skill。当前官方文档列出的自动发现目录包括
仓库 `.agents/skills/` 和用户 `~/.agents/skills/`，并支持目录符号链接。
可在仓库根目录手工运行（已有同名目录时先检查，不覆盖）：

```bash
ln -s ../../skills/jobpilot-cn .agents/skills/jobpilot-cn
```

Windows 可使用有权限的目录链接，或只用已有 `AGENTS.md`。
部分旧环境或自定义安装使用 `~/.codex/skills/jobpilot-cn/`；
只有本机版本确实扫描该位置时才链接进去，不能假定所有版本相同。
启用后可说「使用 jobpilot-cn 检查这份 JD」，也可显式输入 `$jobpilot-cn`。
发现失败时通用兜底：**在仓库根目录打开，告诉 agent 读 SKILL.md**，这里的具体路径是
`skills/jobpilot-cn/SKILL.md`。
参见 [Codex 官方 Skill 文档](https://developers.openai.com/codex/skills/)。

### Cursor

打开完整仓库，直接在 Agent 会话引用 `skills/jobpilot-cn/SKILL.md`。
若本机支持 `.cursor/rules/`，可自行加 `jobpilot-cn.mdc` 指针：

```markdown
---
description: 中文求职建档、手贴JD、申请草稿和面试准备
alwaysApply: false
---
执行中文求职任务时，先读取 skills/jobpilot-cn/SKILL.md 并按需读取步骤。
```

本轮未核实各版本 Cursor 的精确原生 skills 路径与规则激活差异，不把
`.cursor/skills/` 作为已验证安装位置。可从本机规则/技能导入界面选择本目录；
兜底是「在仓库根目录打开，告诉 agent 读 SKILL.md」。
[Cursor 官方文档入口](https://cursor.com/docs)。

### Trae

本轮未核实 Trae 各版本的精确 Skill 路径，不能保证某个 `.trae/skills/` 自动生效。
在支持技能导入的版本中选择 `skills/jobpilot-cn/` 或链接该目录；
若只有项目规则，在规则里写「中文求职先读 skills/jobpilot-cn/SKILL.md」。
通用兜底：「在仓库根目录打开，告诉 agent 读 SKILL.md」。需允许终端和本地文件读写。

### Grok Build

本轮未核实 Grok Build 的精确本地 Skill 发现路径及模型接入能力，不假定
`~/.grok/skills/` 存在。若其工作区支持导入技能，选择本目录；若支持项目说明文件，
添加同样的指针。通用兜底：「在仓库根目录打开，告诉 agent 读 SKILL.md」。
若当前产品不能执行本地 shell，用户自行运行 Python 命令并把结果交回对话；
这种方式只能辅助撰写，不能宣称完整自动文件流程已通过验证。

### Claude Code

现有 `.claude/commands/setup.md`、`apply.md`、`interview.md`、`rank.md`
在中文路径引用通用步骤，同时完整保留国际 Claude Code 流程，包括 URL 获取、门户 CLI 升级链、子代理、公司研究缓存和 setup 搜索词个性化。可以继续输入 `/setup 中文`、`/apply` 并手工粘贴 JD、
`/interview 公司`、`/rank`；也可用上面的中文自然语言提示。
如需原生 Skill 发现，可把 `.claude/skills/jobpilot-cn` 链接到 `../../skills/jobpilot-cn`，
或保留仓库现有 `job-application-assistant` 兼容入口。无需更改 `.claude/settings.json`。
`.claude/settings.local.json` 只是这个宿主的一种模型配置方式。

### Gemini CLI / agy（Antigravity）

Gemini CLI 的官方 Skill 文档列出 `.gemini/skills/`、`.agents/skills/`
等发现位置，按本机版本选择并链接 `skills/jobpilot-cn/`，或在 `GEMINI.md`
放一个指向它的说明。参见 [Gemini CLI Agent Skills](https://geminicli.com/docs/cli/skills/)。
本轮未核实 agy/Antigravity 各版本的精确 Skill 路径，也未实测这些宿主。
不要把 Gemini CLI 的目录机械当作 agy 的目录；优先使用其技能导入/工作区规则界面。
通用兜底：「在仓库根目录打开，告诉 agent 读 SKILL.md」。

## 国产模型在宿主里配置

Skill 使用**宿主当前模型**；不要求 Claude 账户、特定子代理模型或仓库权限配置。
DeepSeek / Kimi / GLM 等是否可用，取决于宿主版本、供应商协议、工具调用能力及账户权限。
先在宿主里发一个不含个人资料的测试请求，并确认能读文件、运行本地命令，再使用本 Skill。
只写模型名而协议不匹配，不能完成接入。

| 宿主 | 配置入口与边界 |
| --- | --- |
| Codex CLI | 在用户 `~/.codex/config.toml` 配置 `model_provider`、`model` 及 `model_providers.<id>` 的 `base_url`、`env_key`；密钥由宿主环境变量读取。当前官方配置只列 `wire_api = "responses"`，供应商或用户自管网关必须实现兼容 Responses 与工具调用，只有 Chat Completions/Anthropic 兼容不能直接替代。 |
| Cursor | 在本机 Models / API Keys 设置中，使用该版本确实支持的供应商或自定义端点；模型 ID、协议和 URL 从供应商官方说明填写。自定义 key 是否支持 Agent 模式需实际验证，不能只看聊天可用。 |
| Trae | 在本机模型设置中选可用国产模型，或在该版本支持自定义模型时填官方端点、模型 ID 和 key。没有自定义入口时使用宿主已提供的模型，不向 Skill 填 key。 |
| Grok Build | 本轮未核实能否替换成国产模型；若本机有 provider / model 设置且官方支持，再按其说明配置。若只支持内置模型，不能靠 Skill 改成国产模型，可换其他支持该供应商的本地宿主。 |
| Gemini CLI / agy | 原生 Gemini 模型配置不等于任意国产模型接入。本轮未核实各版本是否支持自定义国产 provider；仅在宿主或其明确支持的适配器提供相应协议时配置，否则选择支持目标供应商的宿主。 |
| Claude Code | 可选使用 `.claude/settings.local.json` 的 Anthropic 兼容端点；保留的 [模型配置](模型配置.md) 是这个宿主的专门说明，不是其他平台的通用配置。 |

Codex 用户配置结构示意（全是占位符，**不是可直接请求的服务**）：

```toml
model_provider = "domestic"
model = "YOUR_TOOL_CAPABLE_MODEL_ID"

[model_providers.domestic]
name = "User configured domestic provider"
base_url = "https://YOUR_RESPONSES_COMPATIBLE_ENDPOINT/v1"
env_key = "JOBPILOT_HOST_MODEL_KEY"
wire_api = "responses"
```

用户自己在宿主环境设置对应变量；不要在本仓库、聊天、档案或追踪表中填写密钥。
供应商需要适配网关时先独立验证，仓库不附送或安装网关。
配置字段参见 [Codex 官方配置参考](https://developers.openai.com/codex/config-reference/)。
Skill 安装不等于模型服务可达；软件包镜像也不解决模型服务访问。
调用远程模型时简历和 JD 会离开本机，资料范围由用户决定。

## 本地 CLI 走一遍

先让 Agent 按 setup 步骤确认资料，再保存 `profile/confirmed.json`（虚构演练也需标明虚构）：

```bash
python tools/jobpilot.py setup-profile write --in profile/confirmed.json
python tools/jobpilot.py check-jd --in documents/postings/jd.txt
python tools/jobpilot.py scaffold-application --in documents/postings/jd.txt --company 虚构公司 --role 虚构岗位
python tools/jobpilot.py compile documents/applications/虚构公司_虚构岗位/cv_draft.tex --contains 虚构
python tools/jobpilot.py interview-prep --application documents/applications/虚构公司_虚构岗位 --stage 一面
```

排序 JSON 格式见 [rank 步骤](../../skills/jobpilot-cn/steps/rank.md)，执行
`python tools/jobpilot.py rank --results results.json`。所有接收 JD 的命令不传 `--in`
就从标准输入读；JSON 输入也支持 UTF-8 BOM。单独目录演练用 `--workspace <目录>`，
仍从完整仓库调用工具。`compile` 的输出与源文件同目录，不需要手设 TEXINPUTS。
已有申请目录不会被 scaffold 覆盖；已提交材料交给 Agent 另存修订版。

保留新增 `tests/test_jobpilot_skill.py`，仅把命令必须短于 12 行的断言改为检查双路径说明，
使其兼容保留完整上游命令。没有为历史网络测试添加 socket 跳过。
步骤中的旧英文标题/兼容输出路径保留以核对旧档案；默认新输出以 application.json 为准。
本轮验证 CLI 与文档契约，未声称逐一安装运行所有商业宿主。
